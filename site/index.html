Per-session egress visibility for AI coding agents

Know what your agent does with the network.

AI coding agents run shell commands, fetch pages, and install packages on your machine. If one is tricked — by instructions hidden in a page or repository it reads — it can quietly call attacker-controlled servers or send your .env and your tokens somewhere you never intended. EgressEye sits in your harness and answers one question after every tool call.

01

Verdicts in plain words

MALICIOUS
On a blocklist. The URL or its host appears in a downloaded mirror like OpenPhish or URLhaus — checked entirely in memory, on your machine.
suspicious
A deterministic rule matched. Lookalike domains (gihub.com), punycode tricks, embedded credentials, brand-new domains registered days ago, raw-IP URLs.
clean
Known-good infrastructure. The domain is part of a curated allowlist of ~90 development essentials — npm, GitHub, PyPI, and friends.
unknown
No signals either way. We don't guess. This is the honest default — and the reason session-level patterns matter more than verdicts alone.
02

What it catches

Inspection happens before every tool call, on everything the harness sends: commands, tool arguments, file contents the agent writes.

Known-malicious URLs — including defanged ones like hxxp://evil[.]top hidden in scripts the agent writes
Lookalike domains — typosquats, punycode, homoglyphs, raw IP literals
Throwaway infrastructure — domains registered days ago, found via RDAP
Credentials in tool calls — AWS/GitHub/OpenAI/Slack tokens, JWTs, private keys, connection strings, pasted .env files — always redacted on disk
Sharded exfiltration — many small sends to the same host aggregate into one finding that per-request tools structurally miss
Failed attempts too — post-tool-use failures are recorded; a blocked exfil try is still signal
03

Honest limits

EgressEye is a visibility tool, not a sandbox.

A determined compromised agent can bypass hooks. Unknown URLs with no signals stay unknown. Anything that never passes through a tool call — raw sockets, other processes — is invisible to any hook-based tool.

We publish the complete bypass list instead of hiding it. A security tool that hides its limits is marketing, not security.

06

Get started

bash — three commands, then work normally
$ git clone https://github.com/offenselabs/EgressEye && cd EgressEye $ npm install && node dist/cli.js init zcode # pick your harness $ node dist/cli.js update-feeds # mirror the blocklist once # … use your agent normally … $ node dist/cli.js report --last # see what happened

Requires Node 20+. Report-only by default — it never blocks unless you set EGRESS_EYE_BLOCK=1, and then only on feed-confirmed hits. Under the hood: zero runtime dependencies, 70/70 unit tests, a 39-scenario eval corpus, CI on Linux and Windows.

No cookies. No trackers. Static pages.
